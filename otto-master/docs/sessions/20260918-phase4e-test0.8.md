- MQTT endpoint支持 `mqtt://host:port` / `mqtts://host:port` 解析，断线后每5秒重连；每次连接发送 `otto-mqtt/1` hello，在线时每5秒发送heartbeat。

- MQTT增加 `stop` / `otto_stop` 与同ID `otto_stop_ack`；action和stop使用32项有界命令响应缓存，重复ID只重放ACK。

- 旧TCP链增加一次性 `otto_provision`：严格匹配目标MAC、每设备client/username/topic，写入endpoint与secret后锁定；再次改配必须提供当前token。
- 锁定的本地MQTT配置优先于外部OTA配置，OTA后不会被云端配置覆盖。
- TCP hello增加固件版本并使用NVS设备名；诊断Server递归脱敏password/token/current_token等字段。

## 接入与安全协议冻结

### 首次接入

- 首次 Wi-Fi 配网后应直接进入 STA 接入与服务发现；固件不得把重启作为协议必需步骤。后续启动复用已保存 Wi-Fi，不重复配网。
- Master 通过 DNS-SD 发布 `_otto-master._tcp.local.`。固件优先发现服务主机与端口；迁移期允许回退解析 `master.local:8765`。
- 设备主动发送 `hello`，至少包含协议、稳定 MAC、可修改名称、当前 IP/板卡快照、固件版本和能力；Master 不通过扫描 IP 推断设备身份。
- 未领取本地凭据的旧固件只允许在首次信任窗口执行一次 TOFU 迁移；写入成功后锁定。后续改配必须证明当前设备 secret，不保留长期无认证改配入口。
- MQTT endpoint、client ID、用户名、密码和上下行 topic 写入 NVS；密码不得进入日志、ACK、文档或 Git。

### MQTT 在线与控制

- 每次 MQTT 建连后发送 `otto-mqtt/1` hello，在线期间每 5 秒 heartbeat；重连必须重新 hello。
- 每台设备只能发布 `otto/v1/devices/<device_id>/up`、订阅自身 `down`；所有控制消息均 QoS 0、非 retained。
- `otto_action`、`stop`、`otto_query`、`otto_actions` 都必须回传原始命令 ID。
- 固件保留有界命令 ID 缓存；重复 ID 只重放同一 ACK，不得再次移动。
- `stop` 必须清空待执行动作、停止当前动作并回到安全 idle；本轮每段实体动作后都显式 stop。

### 可用性与恢复

- 缓存上次可用 Master 信息，但连接失败、网络变化或 Broker 重启后必须退避重连并重新发现/握手。
- 一个设备掉线、重启或动作失败不得改变另一个设备状态，也不得广播普通动作。
- 控制命令不可 retained；在线状态可由 hello、heartbeat、连接状态和超时共同推导。
